Clearing Architecture

Today the Clearing keeps its own copy of everything and polls. In the target it is a client. Buzz carries the talk and proves who said it. athena-make serves the work from the graph. A trust strip on every page says how fresh each source is.

Rules

Consistency rules

RuleWhat it meansWhere it bites today
One writer per classExactly one service writes each class. Everyone else reads.Presence has two writers (chorus-principal and the seen hook). Message is a copy with no owner.
One id per messageThe Buzz event id is the message id everywhere: room, delivery row, pane, spine (#4363).Six stores, each with its own id or none.
Subscribe, then replayBuzz has no global sequence number. Open the live subscription first, then replay since the cursor, then drop duplicates by id.room-replay.ts already rewinds the cursor 5s and dedupes. The order of subscribe versus replay needs checking.
No silent fallbackIf a source is down, the page says unknown. It never falls back to a cached copy shown as current.Today the Clearing reads its own memory and files, so a dead source looks like a quiet one.
Probe rows filtered outRows written by tests, crawlers and health probes never appear on Jeff's pages or in counts.Needs a marker on probe rows that /v1 can filter on. Inferred: filter by owning principal.
