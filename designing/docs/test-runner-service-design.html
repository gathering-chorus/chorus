Test Runner — Service Design (dynamic, registry-driven)

Owner: Kade. First authoring 2026-08-16 — Jeff's direction, verbatim: "most human engineering teams i led built a framework that allowed us to register and run various types of tests… maybe we need unit test and integration test and ui and perf and security pipelines that pull registered tests" and "even our nightly jobs can flow thru this test runner pipeline." Grounded in a three-agent survey of every runner, the tests-domain registration surface, and per-case selection capability (2026-08-16).

Promise. A test runs because a pipeline SELECTED it from the registry — by type, coverage, and fitness for the moment — never because a script's glob happened to contain it. One selection engine, many pipelines; the nightly is just the pipeline whose selection is "everything."

The problem, measured

Today's runners force block-granularity: one diff line in chorus-hooks buys a 500-test crate plus workspace-wide eslint and tsc — the 8m38s test step in an otherwise seconds-per-step trace (#3905's land, 2026-08-16). Selection is five independent hand-maintained lists of the same TypeScript surface (werk-test's TS_PACKAGES, gate-code's PROJECTS, quality.yml's matrix, run-all-tests' dirs, coverage-floors) — non-identical and drifting: directing/products/cards is in none of werk-test's, so its changes get no jest run at land. Only the nightly discovers; everything else hardcodes.

Source of truth. The registry is the tests domain (urn:chorus:domains:tests, served at :3360/tests). This doc narrates the design; counts and rows live in the graph.

The model — registry, selector, executors, pipelines

Registry (exists): every test is a graph row — filePath, testName, pyramidLayer, covers→Domain, hermeticity, testConcern, quarantine trio, results wired back per case. Selector (half-exists as werk-test --domain/--type): one engine that answers "which registered tests, for this moment" — inputs are a diff (or ALL), a type filter, a hermeticity requirement, and the quarantine set; output is a per-runner execution list. Executors: thin adapters per toolchain that run a NAMED SUBSET and return per-case machine results. Pipelines (Jeff's cut): typed consumers — unit, integration, ui, perf, security, nightly — each a declared Pipeline instance (#3896) whose test step is a registry query, not a script.

The nightly, re-founded

The nightly stops being a separate discovery engine and becomes two registry operations: (1) the full-selection run of the same runner every land uses — same executors, same per-case wire-back, same UNMEASURABLE semantics; (2) the reconciler — on-disk globs vs registry (undeclared_gaps already exists) both directions: a test on disk not registered is a red finding; a registered test whose file is gone is a vanished row. Discovery becomes the census check, not the selection mechanism.

Registration gaps this design closes

  • One type vocabulary. The commit gate allows unit…security; the shape splits pyramidLayer/testConcern with different values — a @test-type: security file is unreachable by its declared type today. Unify (Silas shape ruling), and the gate's vocabulary becomes the shape's.
  • The header enters the graph. @test-type is enforced at commit then thrown away; the crawler re-guesses pyramidLayer each cycle. The hydrator ingests the authored header; heuristics only fill absence, flagged as inferred.
  • Results get a clock. TestResult carries no runTs/cardId on the deployed shape — per-test history and evidence-driven quarantine (flake detection) are unqueryable. Add them (the declared mintKey already expects runTs).
  • cargo-nextest adopted for listing + per-case JSON + real subset runs on stable.

Migration — strangler-fig, retirement-gated

  1. Unit pipeline first: selector narrows werk-test's jest leg to registered-affected tests (jest already has every needed flag). Negative proof: a fixture diff whose covering tests are known must run exactly those and refuse to under-select (#3734).
  2. Retire TS_PACKAGES and the other four lists one consumer at a time, each with a retirement gate so no glob-runner survives as fallback — the "works sometimes so both stay alive" trap is the named enemy.
  3. Nightly cutover last: full-selection + reconciler replaces nightly-suites' own globs; per-owner red routing and the wall-clock cap carry over unchanged.
  4. Every cutover's retired list becomes registry rows first — the census gets honest as a side effect.

Not in scope

  • Replacing the toolchains (jest/cargo/bats stay; nextest is an addition, not a rewrite).
  • Coverage floors and ratchets — they remain werk-code gates, consuming the same selection where file-scoped.
  • Auto-registering tests the reconciler finds — surfacing, never spawning (#3190's tagging rule).
