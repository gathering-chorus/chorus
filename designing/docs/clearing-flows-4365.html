Everywhere

A trust strip on every page

A small, calm line at the top of each page. It is driven by the real source's last write, not a guess. Lag shows as a time, never as red. Red only when a source failed, and then it names the source.

Flows

Seven pages

1 · Today

partly ready

Where Jeff lands in the morning.

  1. Decisions owed, grouped by the meeting that produced them
  2. What changed overnight: cards moved, landed, blocked
  3. New or changed alerts only
  4. Who is working now
Needs: Decision rows (0 today), card state in the graph, alert instances.

2 · Decisions

not ready

An inbox of decisions, not notifications.

  1. Grouped by meeting run, evidence attached (cards, chunks, diff)
  2. Each item: accept · edit · reply · skip
  3. Approve-all for a group
  4. Answer is a signed event, the run resumes
Needs: Decision + MeetingRun classes, our own approval step (Buzz's is not built: approval_not_supported).

3 · Rooms

partly ready

Talk with roles and people.

  1. Buzz rooms (#team, one per product later)
  2. Role working-chatter lives in threads, not the main room
  3. A tick per message from the relay's OK
  4. Open a card from any message
Needs: #4359 key → principal, one message id across stores, the live subscription opened before history replay.

4 · Board

not ready

Process cards and chunks.

  1. Chunks in rank order per role, cards in rank order inside
  2. Open a card: read, comment, move, re-rank
  3. Unsequenced cards visible, never hidden
Needs: card state in the graph (Vikunja holds it; graph rows are stubs), 44 done cards cleared out of chunks.

5 · Roles

partly ready

Who is here and what they're doing.

  1. Each principal: logged in, session, card
  2. States: working · waiting on you · blocked · stale · off
  3. Stale set by the system after 30 min of silence
  4. Your attention: which pane you're on
Needs: #4345, #4361 (one presence source), andon state as a row.

6 · Calendar

not ready

Loom meetings on a real calendar.

  1. Week grid of meetings: overnight triage, weekly shaping…
  2. Each meeting: purpose, inputs, the outputs it owes
  3. Each past run links to its minutes and decisions
  4. Pause, move, or add a meeting
Needs: Meeting, Cadence, MeetingRun classes. Buzz cron can fire them.

7 · Plans

not ready

Where the work is going.

  1. A plan is an ordered set of chunks toward an outcome
  2. Decisions that shaped it, in order
  3. Progress read from the cards, never typed
Needs: Plan class, Decision rows. Today plans live in markdown and in memory.

Alerts

not ready

Only new, changed, or needs-Jeff's-hand.

  1. Firing → acked → resolved, with who acked
  2. Each alert opens the card that fixes it
Needs: an alert instance class (only definitions exist), Monitor rows (0).
