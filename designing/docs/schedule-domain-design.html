Schedule — Domain Design schedule domain · #4081

Silas (owner) · drafted by Wren · 2026-10-11 · live rows: GET /v1/schedule/… on the model door

Answers "what runs when" from the machines themselves. A job that went quiet shows up against the schedule it was supposed to keep.

Where it sits

Borg operating stream
  Read     the hourly services crawl (com.chorus.service-harvest) reads every timed launchd unit
  Surface  a job whose last run is older than its schedule; a job that exited non-zero

domain  schedule  (owner silas, step proving, graph urn:chorus:domains:schedule)
  └─ ScheduledJob
       parent  runsService → Service   (the service the job runs)
       onMachine → Machine             (library, bedroom)

What a row says

fieldmeaning
launchdLabelthe unit, e.g. com.chorus.nightly-suites
scheduleKindcalendar · interval
scheduleSpecevery calendar entry, not only the first ("daily 03:00", "Mon 09:30"), or the interval
intervalSecsfor interval jobs
enabledfrom launchctl's disabled list, which overrides the plist's own Disabled key
runs · lastExitCodefrom launchctl print, on both machines (Bedroom over ssh). "Never exited" means it hasn't run, which is not exit 0.
logPathStandardOutPath

Rules

one writer        the services crawl writes these rows; there is no second harvester
measured only     every field comes from the plist or launchctl and none is typed in;
                  a machine that can't be read gives unmeasured, never blank
no crontab        cost-metrics is a launchd unit now (backup-pods retired by #4705); crontab is empty
moved home        rows created in schedule; the old copies are retired from services in the same land

The page

/athena/schedule.html is the generic page that draws any collection from its shape, preset to /v1/schedule/scheduledjobs. No per-class HTML.

Open

Last-run time is not read: launchctl print has no timestamp. The run count and last exit are read.
