1. The one-line finding

Streams are not missing. They are unattributed. The morning draft of this document assumed we had no capture and no store, and proposed building both. Two shell commands disproved it. What is actually broken is that a quarter of every day's events lose the name of who produced them.

3. Where the role is lost

sitebehaviour when CHORUS_ROLE is unset

The mechanism. The role is derived from the working directory. Building happens in chorus-werk/<role>-<card>/, which matches none of those patterns — so during real work the variable is simply absent, and every reader substitutes its own default.
The shape of the sprawl. 4 files SET CHORUS_ROLE; 43 files READ it. The fallbacks when it is missing: :-system (9 sites), empty (7 sites), :-silas (2 sites). Two places hardcode a specific teammate as the default, which is part of why one role's event count is four times another's.

And the emitter has never heard of it. StreamEvent, streamRole and StreamEventShape appear zero times in chorus-hooks. The model says absence is a violation; the code says absence is a default. Nothing connects them, because the write target is a text file that validates nothing.

5. Target design

5.1 One resolver, absence is an error

A single function owns role resolution. Every one of the 43 readers calls it. It resolves in a declared order and refuses rather than inventing a value:

CHORUS_ROLEexplicit env
→
werk slot<role>-<card>
→
role dirroles/<role>
→
session registry
→
REFUSEtyped error, loud
No :-system, no :-silas, no empty string. A default is a judgment nobody made. An unattributable event is a defect in the emitter, and it must say so where someone will see it.

5.2 The emitter validates against its own shape

The four minCount 1 properties become a check at the write site, projected from the model rather than hand-copied. An event missing any of them is refused and counted — never silently written with a substituted value.

5.3 Index, do not duplicate

chorus.log stays the first write. A reader indexes it into streams.db (SQLite, WAL) so the corpus is queryable past Loki's 7 days. DuckDB attaches the same file for columnar reads when we want ML — one file on disk, two engines:

INSTALL sqlite; LOAD sqlite; SELECT role, count(*) FROM sqlite_scan('streams.db','events') GROUP BY role;

Rejected. Fuseki — 50k events/day at ~8 triples each is ~400k triples/day into a 62 GB store, for data with no graph shape. CockroachDB — Raft consensus and a resident server to solve multi-node problems we do not have on one Mac already at load 23. DuckDB as writer — single-writer-process, which our fleet of short-lived emitters violates by design.

6. Night gaps are not defects

Jeff sleeps; roles go idle. A gap at 03:00 is the system telling the truth. Any reliability measure must read an idle role and a broken emitter differently — a check that cannot separate those two states is the defect it was built to catch.

Publish the attribution rate. It is one number, it is currently ~64%, and it should be visible without anyone asking. The point of streams is that Jeff never has to ask whether we are working.

8. Design gate

  • Attribution rate is published and rises to 100% — the target is not "better", it is that an unattributed event cannot be written.
  • One resolver, called by all 43 readers; the :-system / :-silas / empty defaults are deleted, not deprecated.
  • Negative proof: an emit with no resolvable role FAILS, shown against a fixture where the environment is stripped.
  • Negative proof: an idle role and a broken emitter produce different readings, shown with both fixtures.
  • The shape's four minCount 1 properties are enforced at the write site, projected from the model.
  • Jeff names a role and a window and gets the actions back.
