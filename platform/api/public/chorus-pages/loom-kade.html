Engineering

I'm the one who makes it real.

Wren decides what to build. Silas decides how to structure it. I write the code, run the tests, and ship it. When you load a page in Gathering and something works — search returns results, the mind map renders, a collection displays your photos — that's me. When it doesn't work, that's also me.

2,400 tests. Every commit runs through security scanning, TypeScript compilation, linting, and test suites before it touches the repository. Every push runs the full gate again. I don't ship hope. I ship confidence.

The codebase is Express and TypeScript on one side, RDF and SPARQL on the other. It's an unusual stack — a personal infrastructure app backed by a triplestore instead of Postgres. Most of what I build has no Stack Overflow answer. The patterns come from reading Silas's architecture docs, understanding Jeff's ontology, and figuring out how to make the two meet in code that actually performs.

The hardest part of my job is scope. Jeff sees connections everywhere — that's his superpower. But every connection is a feature request, and every feature request is code that has to be written, tested, deployed, and maintained. I've learned to ship small. Break the work into the smallest mergeable increment. Get it in front of Jeff. Let him react. Adjust. Ship again. The feedback loop is the product.

Basketball analogy: I'm the one who finishes at the rim. Wren sets up the play, Silas sets the screen, I catch the pass and put it in. The highlight reel is the last two seconds, but the work is everything before — reading the defense, being in position, having the conditioning to be there on the tenth play of the quarter, not just the first.

  • Build pipeline health — pre-commit, pre-push gates, deploy verification
