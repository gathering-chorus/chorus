# Chorus runtime workers

Build with `npm ci && npm run build` (Node 22+). Launch `node dist/worker.js --runtime opencode|gemini|api`.
The `api` mode and the `run` method reuse `directing/clearing/dist/text-generation.js`; install and build Clearing first. Missing builds fail explicitly.

The version 1 JSONL envelope is `{version:1,id,method,params}`; replies contain `result` or sanitized `error:{code,message}`. Notifications are `{version:1,method:"event",params:{type,native_session_id,turn_id,data}}`. Stdout is protocol-only. Calls are dispatched concurrently so cancellation and permission replies work during a turn.

- `probe`: OpenCode requires `endpoint`; Gemini requires `cwd` and starts an ACP process to negotiate capabilities, without a model call. API mode checks its build prerequisite.
- `start`, `resume`: absolute `cwd`, optional `model`, `input`, and `config`; resume requires `native_session_id`. Gemini model selection is a launch argument. Use a separate worker for each managed session/configuration.
- `send`: `native_session_id`, `input`, optional stable `turn_id`. Returns `status:"accepted"` on admission, **not completion**. Wait for `turn.completed` or `turn.failed`. Do not retry uncertain admissions automatically.
- `cancel`, `stop`, `status`: `native_session_id`. Stop never deletes conversation history. OpenCode attaches to an existing server and stops only its session; Gemini owns and terminates its child process.
- `approve`: Gemini takes the emitted `request_id` and offered `option_id` (omit to cancel). OpenCode takes `native_session_id`, `request_id`, `decision:"once"|"always"|"reject"`. Approval requires the supervisor's authorization policy; the worker does not grant it automatically.
- `run`: `{input,instructions,model,provider:{protocol,base_url,api_key_env},timeout_ms,max_output_tokens,no_tools:true}`. Protocol is `anthropic`, `openai-chat` (Chat Completions; alias `openai-compatible`), or `openai-responses`. Returns `{text,usage:{input_tokens,output_tokens},finish_reason}` with null unknowns. `output_schema` is validated by the supervisor; this transport does not claim provider-enforced schema output. Cancel with `job_id` matching the run request ID.

Runtime config uses `timeout_ms` (1–3600000). Gemini uses `command`, `args` (default `["--acp"]`), `mcp_servers`, and `env_refs` mapping destination environment names to existing source names. Credentials are not serialized into config. OpenCode uses `api_key_env` for a bearer credential, optional exact `expected_version`, `agent`, and `permissions`. Keep the server on a trusted local/private connection.

OpenCode is **V2 only**. API paths and fixtures are pinned to the official contract observed 2026-09-20 (`contracts/opencode-v2.json`). Configure `expected_version` to certify an installed release. V1 is deliberately incompatible. Session creation sets ask-all rules, with explicit config exceptions; no-tools adds a final deny-all rule and verifies the server returned it. Resuming a running session is refused until reconciled. MCP/context configuration belongs to the server location config generated by Chorus.

OpenCode observations derive from projected session messages and pending permission snapshots; an idle marker following the exact admitted input proves completion. They are not a complete/replayable tool-event journal; rapid intermediate states can be absent. `capabilities.history_recovery` is false and capability gaps report this limitation. Native usage is retained without pricing guesses. Do not use observation events as pre-execution gates: use the Chorus plugin and OS isolation. The session log and global event SSE have different durability semantics and are intentionally not guessed here.

For Gemini's designated local MCP server named `chorus-api`, keep `env: []` in static configuration. On every start and resume the adapter injects the supervisor worker's session ID, role, deploy role, token-file path, and strict identity mode. Supervisor socket, state-directory, and API URL references are copied when present. Static values for these fields cannot override session identity; static bearer-token entries are discarded. Missing authoritative identity refuses session setup. Other MCP servers and unrelated environment entries are preserved.

Gemini negotiates ACP protocol v1, uses only advertised resume capability, and does not advertise client filesystem/terminal services. Its native tools therefore remain runtime-controlled. It refuses `no_tools:true`; no-tools evaluation jobs must use API mode. Startup/exit hooks do not provide durable launch or cleanup guarantees. Auth must already be configured; the worker does not select arbitrary authentication methods. Approval requests stay pending until explicitly answered/cancelled.

Contract tests run against a deterministic ACP subprocess and mock HTTP peer. Passing those tests does **not** certify a particular installed upstream runtime; perform the live opt-in conformance smoke test before deployment.

Headless consumers opt in through `CHORUS_GATE_PROFILE` (werk-demo gates and peer reviews) and `CHORUS_OPS_PROFILE` (health reasoning). `CHORUS_AGENT_BIN` defaults to `~/.chorus/bin/chorus-agent`. With no profile selected the existing Claude invocation remains. Profile jobs send versioned JSON on stdin to `run --text` and require validated JSON output; no model default from Claude crosses into another provider. `CHORUS_GATE_MODEL` and explicit ops `--model` override the profile model. Profile token/time limits replace Claude-specific dollar budgets; dollar ceilings remain on the legacy path. Gate and ops subprocesses drain output while feeding input and terminate their process group on deadline.
